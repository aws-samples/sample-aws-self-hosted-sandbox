## 一、覆盖范围

本轮验证包含：

- control-plane 与 node-agent 的 `/metrics`、`/livez`、`/readyz`
- 集群内 Prometheus、Alertmanager、Grafana
- control-plane ServiceMonitor、node-agent PodMonitor
- 5 类告警规则和 8 面板 `Sandbox Platform` Dashboard
- 快照 SHA-256 manifest、恢复前完整性校验和损坏注入

- Amazon Managed Grafana（AMG）经 VPC Interface Endpoint 查询 AMP
- Helm 长时间升级的 EKS token 刷新
- Terraform apply 后的零漂移检查

不在本轮范围内：

- 创建 AMG workspace 本身（复用已有 workspace）
- CloudWatch Logs 集中日志、OpenTelemetry tracing
- Alertmanager 外部通知接收器（PagerDuty、SNS、飞书等）

## 四、测试中发现并修复的问题

### 4.1 Helm upgrade 的 EKS token 过期

初次长时间 upgrade 在 post-upgrade hook 阶段出现：

```text
clusterrolebinding.yaml failed: Unauthorized
```

原因是 Kubernetes/Helm provider 使用一次性
`data.aws_eks_cluster_auth.main.token`，Terraform 启动后约 15 分钟 token 失效。

修复：两个 provider 均改用可刷新的 exec credential：

```hcl
exec {
  api_version = "client.authentication.k8s.io/v1beta1"
  command     = "aws"
  args        = ["eks", "get-token", "--cluster-name", var.cluster_name, "--region", var.region]
}
```

清理 pending revision、重新 apply 后，revision 5 为 `deployed`。

### 4.2 Grafana 密码出现在 Helm metadata

把 `adminPassword` 放进普通 `values` 会让 Helm provider 的 release metadata 在 plan
diff 中出现敏感字段。修复后密码改由 `set_sensitive` 传入。

验证：

- Terraform state 中 `set_sensitive` 名称为 `grafana.adminPassword`
- Helm metadata 不包含当前 Grafana 密码字面值
- 后续 `terraform plan` 不再展示密码
